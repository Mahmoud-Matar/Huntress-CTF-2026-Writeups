The public wrapper class delegates `score(String)` to the Scala singleton, so the changed implementation is in `Day24Vulnerable000$.score` versus `Day24Corrected000$.score`.

The vulnerable build checks `input.nonEmpty` and then reads `input.charAt(0)`. This handles an empty string, but a null input reaches the string operation without a null guard and can throw instead of returning the fallback. The corrected build wraps the input in `Option`, filters for nonempty strings, maps to the first character, and uses `-1` when the option is empty. That guards both null and empty input while preserving the first-character score for valid input.

The corrected main implementation adds the `score` lambdas for the nonempty predicate, first-character mapping, and `-1` fallback. The same comparison also showed renumbered constant-pool entries and corresponding compiler-generated bytecode changes; these are consequences of the implementation change rather than separate behavioral fixes.
